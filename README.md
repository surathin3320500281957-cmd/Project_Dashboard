# แดชบอร์ดหน่วยความรับผิดชอบ — การเคหะแห่งชาติ

เอกสารนี้สรุปโครงการแดชบอร์ดทั้งหมด เผื่อไว้สำหรับเปิดแชทใหม่แล้วอ้างอิงต่อได้ทันที

## 1) ภาพรวมโครงการ

แดชบอร์ดแบบ **ไฟล์ HTML เดียว** (single-file, ไม่มี backend, ไม่ต้องเชื่อมอินเทอร์เน็ต) มี **3 tab**:

| Tab | เนื้อหา | ระดับข้อมูล |
|---|---|---|
| **ภาพรวม** | สรุปทุกโครงการจากชีต "สรุปหน่วยเต็ม" | ระดับโครงการ (185 แถว) |
| **หน่วย Active** | หน่วยที่มีสัญญา/เช่าเหมา/รอโอน จาก 3 ชีตธุรกรรม | ระดับหน่วย/MAT (36,220 แถว) |
| **หน่วยว่าง** | หน่วยว่างจากชีต "หน่วยว่าง" | ระดับหน่วย/MAT (2,660 แถว) |

**ไฟล์ล่าสุด:** `LAA_Dashboard_หน่วยความรับผิดชอบ.html` (~990KB)

สร้างจากไฟล์ Excel `DBหน่วยความรับผิดชอบ.xlsx` ซึ่งมี 6 ชีต:

| ชีต | หน้าที่ | จำนวนแถว |
|---|---|---|
| `อธิบาย` | หมายเหตุ SQL query ต้นทาง (ไม่ใช่ข้อมูลจริง) | 29 |
| **`สรุปหน่วยเต็ม`** | **ชีตหลักระดับโครงการ** ใช้เป็น context (กอง/สำนักงาน/ประเภท ฯลฯ) ให้ทุก tab | 185 |
| `หน่วยว่าง` | ข้อมูลระดับหน่วย ใช้ทำ tab "หน่วยว่าง" | 4,822 |
| `เช่าซื้อรอโอน` | ข้อมูลระดับหน่วย ใช้ทำสถานะ "ติดค้ำประกันฯ/รอโอน" ใน tab "หน่วย Active" | 8,566 |
| `มีสัญญา` | ข้อมูลระดับหน่วย ใช้ทำสถานะ "เช่า/เช่าซื้อ/จะซื้อจะขาย" ใน tab "หน่วย Active" | 17,820 |
| `เช่าเหมา` | ข้อมูลระดับหน่วย ใช้ทำสถานะ "เช่าเหมา" ใน tab "หน่วย Active" | 11,796 |

## 2) หลักการ Join ข้อมูลข้ามชีต (สำคัญที่สุด)

**หลักการทำงาน:** ชีต "สรุปหน่วยเต็ม" มีสูตร `COUNTIFS` ฝังไว้ในคอลัมน์สถานะหน่วย (W-AG) ที่ดึงยอดนับจาก 4 ชีตธุรกรรม โดยแต่ละสูตรมีเงื่อนไข **ไม่เหมือนกัน** ทั้ง join key (คอลัมน์ไหนคือรหัสโครงการ) และเงื่อนไขกรอง — วิธีสร้าง 2 tab ใหม่ (หน่วย Active, หน่วยว่าง) คือ **อ่านสูตร COUNTIFS แต่ละคอลัมน์แล้วแปลงกลับเป็นตรรกะ join/filter ในโค้ด JS** เพื่อให้ได้ข้อมูลระดับหน่วยจริงที่ผลรวมตรงกับตัวเลขในสูตรเป๊ะ (ตรวจนับด้วย Python ยืนยันแล้วทุกจุด — ดูหัวข้อ 2.4)

### 2.1 Tab "หน่วย Active" — join 3 ชีต

| สถานะ | ชีตต้นทาง | join key (=รหัสโครงการ) | เงื่อนไข |
|---|---|---|---|
| (1) เช่า | `มีสัญญา` | คอลัมน์ `D` (PROJ) | `O` (CONTRACT_TYPE_CODE) = `"50"` |
| (2) เช่าเหมา | `เช่าเหมา` | คอลัมน์ `E` (PROJ_CODE) | ไม่มีเงื่อนไขสถานะ — นับทุกแถวของโครงการ |
| (3) เช่าซื้อ | `มีสัญญา` | คอลัมน์ `D` | `O` = `"20"` |
| (4) จะซื้อจะขาย | `มีสัญญา` | คอลัมน์ `D` | `O` = `"10"` **AND** `Y` (CUST_STATUS_NAME) = `"กำลังผ่อนชำระ"` |
| (5) ติดค้ำประกันฯ | `เช่าซื้อรอโอน` | คอลัมน์ `F` (PROJ_CODE) | `V` (CONTRACT_STATUS) มีคำว่า `"ค้ำประกัน"` |
| (6) รอโอน | `เช่าซื้อรอโอน` | คอลัมน์ `F` | `V` มีคำว่า `"รอโอน"` |

คอลัมน์ที่ดึงมาใช้จริงต่อ 1 หน่วย: `MAT`, `HOUSE_NO_ACT`(บ้านเลขที่), สถานะ (derived ข้างบน), ค่าอ้างอิง (`Y` หรือ `V` แล้วแต่แหล่ง) — join กับข้อมูลโครงการ (กอง/สำนักงาน/ประเภท/รูปแบบหารายได้/ลักษณะอาคาร/ชื่อโครงการ) ด้วยรหัสโครงการอีกที

**⚠️ ข้อยกเว้นที่รู้ตัวแล้ว:** ชีต `มีสัญญา` ยังมี `CONTRACT_TYPE_CODE = "80"` อีก 1,585 แถว (สถานะสัญญาปกติ/ติดตามหนี้ ไม่ใช่สัญญาปิด) ที่ SQL view ต้นทาง (`V_CONTRACT_ACTIVE_DM` ในชีต `อธิบาย`) นิยามว่าเป็น "สัญญา active" เหมือนกัน แต่สูตร COUNTIFS ในไฟล์ Excel ปัจจุบัน **ไม่ได้รวม code 80 เข้ากับคอลัมน์ไหนเลย** — เจ้าของไฟล์ยืนยันสูตรที่ถูกต้องแล้วว่า **code 80 ต้องถูกรวมเข้ากับสถานะ "(3) เช่าซื้อ" เดิม** (ไม่ใช่สถานะใหม่แยกต่างหาก):
```
=COUNTIFS('มีสัญญา'!O:O,"20",'มีสัญญา'!D:D,'สรุปหน่วยเต็ม'!J2)
+ COUNTIFS('มีสัญญา'!O:O,"80",'มีสัญญา'!D:D,'สรุปหน่วยเต็ม'!J2)
```
ตอนนี้ตัวเลข "หน่วย Active" ในแดชบอร์ด (ทั้ง 3 tab) ยังคง**ไม่รวม code 80** เพื่อให้ตรงกับตัวเลขที่มีอยู่ในไฟล์ Excel ปัจจุบัน 100% ก่อน — **รอไฟล์ Excel ฉบับใหม่** แล้วค่อยปรับ join logic ของสถานะ "(3) เช่าซื้อ" ให้ครอบคลุมทั้ง `O="20"` และ `O="80"` (ไม่ต้องเพิ่มการ์ด/สถานะใหม่ในหน้า UI เลย ยังคง 6 สถานะเท่าเดิม)

จุดสังเกตอีกจุด: เงื่อนไข "(4) จะซื้อจะขาย" (`O="10"` AND `Y="กำลังผ่อนชำระ"`) เข้มงวดมาก ในข้อมูลจริง code 10 มี 252 แถว แต่มีแค่ 1 แถวที่ตรงเงื่อนไขนี้ — ยืนยันแล้วว่าเป็นพฤติกรรมที่ตั้งใจ ไม่ใช่บั๊ก

### 2.2 Tab "หน่วยว่าง" — join 1 ชีต แต่ดึงคอลัมน์เพิ่ม

| ที่มา | คอลัมน์ | ใช้เป็น |
|---|---|---|
| `หน่วยว่าง!O` | PROJ_CODE | join key (=รหัสโครงการ) |
| `หน่วยว่าง!Q` | CL_MATERIAL_NO | MAT |
| `หน่วยว่าง!W` | HOUSE_NO_ACT | บ้านเลขที่ |
| `หน่วยว่าง!AM` | STOCK_STATUS | ว่างพร้อมขาย / ว่างไม่พร้อมขาย |
| `หน่วยว่าง!AU` | TYPE_NAME | เช่า / เช่าซื้อ → ใช้เป็น **"รูปแบบหารายได้" ระดับหน่วย** (แทนค่าระดับโครงการที่ใช้ใน tab อื่น) |
| `หน่วยว่าง!BB` | CONTRACT_STATUS | คอลัมน์อ้างอิงในตารางรายละเอียด |
| `หน่วยว่าง!BC` | END_GUARANTEE_DATE | สิ้นสุดค้ำประกัน |
| `หน่วยว่าง!BD` | REDATE | วันที่ซื้อคืน |
| `หน่วยว่าง!BE` | DATEK | จำนวนวันซื้อคืน |
| `หน่วยว่าง!BF` | STOCK_RMK | หมายเหตุ |
| `หน่วยว่าง!BG` | REF_NO | อ้างถึง |

**สถานะ 4 แบบ** (มาจาก `AM` × `AU` ผสมกัน — ตรงกับ 4 คอลัมน์ COUNTIFS เดิมในสรุปหน่วยเต็ม `AD-AG`):
`AM="ว่างพร้อมขาย"` + `AU="เช่า"` → ว่างพร้อมขาย(เพื่อเช่า) · `AM="ว่างไม่พร้อมขาย"` + `AU="เช่า"` → ว่างไม่พร้อมขาย(เพื่อเช่า) · เช่นเดียวกันกับ `AU="เช่าซื้อ"` → …(เพื่อขาย)

คอลัมน์เหล่านี้ (CONTRACT_STATUS ถึง REF_NO) **ไม่เคยถูกฝังไว้ในไฟล์มาก่อน** (ตอนทำ tab "หน่วย Active" ใช้ข้อมูลที่ฝังไว้แล้วจากฟีเจอร์ audit เดิม ซึ่งมีแค่ MAT/บ้านเลขที่/สถานะ/หมายเหตุสั้นๆ) — ตอนทำ tab นี้จึงต้อง**ดึงข้อมูลใหม่จากไฟล์ Excel ต้นฉบับโดยตรง** อีกรอบ แล้วบีบอัดเป็นก้อนข้อมูลใหม่ (`VC64`) เพิ่มเข้าไปในไฟล์ HTML

### 2.3 กติกาการ join ที่ใช้ร่วมกันทุก tab

- ถ้ารหัสโครงการจากชีตธุรกรรมไม่มีอยู่ในชีต "สรุปหน่วยเต็ม" (185 โครงการ) → **ตัดทิ้ง** ไม่นำมาแสดง (ตรงพฤติกรรมเดิมของสูตร COUNTIFS ที่นับได้เฉพาะโครงการที่มีแถวอยู่ในสรุปหน่วยเต็มเท่านั้น)
- ข้อมูลส่วนบุคคล (ชื่อลูกค้า/เลขบัตร ปชช./เบอร์โทร) **ตัดออกทั้งหมด** ทุก tab — เก็บเฉพาะ MAT/บ้านเลขที่/สถานะ/ค่าอ้างอิงที่จำเป็นสำหรับตรวจสอบยอด

### 2.4 การตรวจทานความถูกต้อง (ยืนยันด้วย Python)

| รายการ | ผลตรวจ |
|---|---|
| ผลรวม COUNTIFS ทั้ง 10 สูตรใน "สรุปหน่วยเต็ม" เทียบกับผลรวมจริงในไฟล์ | **ตรงกัน 100%** |
| หน่วย Active ที่ join ได้ (36,220 หน่วย) เทียบกับผลรวม `active_total` ใน RAW_DATA | **ตรงกัน 36,220 = 36,220** |
| หน่วยว่างที่ join ได้ (2,660 หน่วย) แยกตาม 4 สถานะ เทียบกับ `vacant_ready_rent/notready_rent/ready_sale/notready_sale` | **ตรงกันทุกตัว** (1,032 / 282 / 775 / 571) |

## 3) สถาปัตยกรรมไฟล์ (เทคนิคบีบอัด)

ไฟล์เดียวจบ ไม่มีไฟล์แยก ไม่มี backend ใช้เทคนิค **gzip + base64** ฝังข้อมูลเป็นตัวแปร JS:

```
ขั้นตอนตอนสร้างไฟล์ (ทำครั้งเดียว, ฝั่ง Python):
1. แปลงแต่ละแถวเป็น array (ไม่ใช่ object ซ้ำคีย์) → {cols:[...], rows:[[...],[...]]}
2. JSON.dumps แบบไม่มีช่องว่าง (separators=(',',':'))
3. gzip compress (level 9)
4. base64 encode → เก็บในตัวแปร JS

ขั้นตอนตอนเปิดไฟล์ (ฝั่งเบราว์เซอร์):
Base64 → atob() → DecompressionStream('gzip') (Web API มาตรฐาน ไม่ต้องใช้ไลบรารีเพิ่ม)
→ JSON.parse → คืนรูป array-of-objects ด้วย cols mapping
```

| ตัวแปร | เนื้อหา | โหลดตอนไหน | ขนาด (บีบอัดแล้ว) |
|---|---|---|---|
| `DB64` | 185 โครงการ × 38 คอลัมน์ (ระดับโครงการ) | ตอนเปิดไฟล์ (ทุก tab ใช้) | ~13.6 KB |
| `PB64` | 38,880 รายการตรวจสอบระดับหน่วย จาก 4 ชีตธุรกรรม (audit เดิม + ใช้สร้าง tab หน่วย Active) | ตอนเปิดไฟล์ | ~334 KB |
| `CS64` | CUST_STATUS_NAME จริงจากชีต "มีสัญญา" 15,863 แถว (คีย์ด้วย MAT) — ดู bug fix ในหัวข้อ 9 | ตอนเปิดไฟล์ | ~52.5 KB |
| `VC64` | 2,660 หน่วยว่าง พร้อมคอลัมน์เพิ่มเติม (CONTRACT_STATUS ฯลฯ) | **lazy** — ถอดรหัสตอนคลิกเข้า tab "หน่วยว่าง" ครั้งแรกเท่านั้น | ~28 KB |

**ไลบรารีที่ฝังในไฟล์ (inline, ไม่มี CDN ภายนอก — กันปัญหาเครือข่ายองค์กรบล็อก CDN):**
- Chart.js (UMD) — ใช้ทำกราฟโดนัททั้ง 3 tab
- SheetJS `xlsx.mini.min.js` — สำหรับ export Excel

**ข้อกำหนดเบราว์เซอร์:** ต้องรองรับ `DecompressionStream` (Chrome/Edge 80+, Firefox 113+, Safari 16.4+)

**หลักการโหลดข้อมูลแบบ lazy:** tab "หน่วย Active" และ "หน่วยว่าง" จะ**ไม่ประมวลผลอะไรเลยจนกว่าจะถูกคลิกเข้าไปครั้งแรก** (ไม่ทำให้ตอนเปิดไฟล์ครั้งแรกช้าลง) — ข้อมูลระดับหน่วยของ "หน่วย Active" มาจากก้อน `PB64` ที่โหลดไว้แล้วตั้งแต่ต้น (แค่รอ filter+join ตอนคลิก tab) ส่วน "หน่วยว่าง" ต้องถอดรหัส `VC64` เพิ่มด้วย (เพราะเป็นก้อนข้อมูลใหม่ที่ไม่ได้โหลดพร้อม DB64/PB64)

## 4) ฟีเจอร์ในแดชบอร์ด

### 4.1 แถบสลับ tab
`[ภาพรวม] [หน่วย Active] [หน่วยว่าง]` อยู่บนสุดของหน้า คลิกสลับได้ทันที (ไฟล์เดียว ไม่โหลดหน้าใหม่)

### 4.2 Tab "ภาพรวม" (ระดับโครงการ)

**การ์ด KPI (4 ใบ):** หน่วยเต็ม (hero, น้ำเงิน-ม่วง) / หน่วย Active (เขียวมิ้นท์) / ว่างพร้อมขาย (ทอง) / ว่างไม่พร้อมขาย (แดง) — คลิกการ์ดเพื่อเลือกเมตริกใช้กับกราฟ + กรองตาราง (คลิกซ้ำยกเลิก)

**การ์ดย่อยแบบคลิกกรองได้ (badge):** ภายในการ์ด "หน่วย Active" มี 6 badge สถานะ, "ว่างพร้อมขาย"/"ว่างไม่พร้อมขาย" มี 2 badge (เพื่อเช่า/เพื่อขาย) — คลิก badge ใดก็กรองทั้งหน้าตามสถานะย่อยนั้นได้เลย โดยการ์ดแม่จะขึ้นกรอบไฮไลต์สีของตัวเองบอกว่ากำลังกรองอยู่

**กราฟ:** โดนัทตามกอง (ค่าตัวเลขมีพื้นหลังทึบให้อ่านง่าย, ขนาดพื้นที่ ~1/3 ของแถว) · อันดับสำนักงาน (ทั้งหมด ไม่ตัด Top 10 แล้ว) · อันดับโครงการ (Top 10) — ป้ายชื่อในกราฟอันดับเป็นแคปซูลสีม่วง ไม่หดตามความยาวแท่ง

**ตัวกรอง:** กอง, ประเภทโครงการ, กลุ่มโครงการ, รูปแบบการหารายได้, ลักษณะอาคาร, จังหวัด + ค้นหาอิสระ — ทำงานแบบ **cross-filter ที่ไม่กรองตัวเอง** (ตัวเลือกในแต่ละ dropdown คำนวณจากตัวกรองอื่นๆ เท่านั้น) พร้อม filter chip สีต่างกันตามมิติ ใต้แถบตัวกรอง กดลบทีละตัวได้ รวมถึงมี chip แยกสำหรับตัวกรองจากการ์ด/badge ด้วย

**ตารางสรุป (กอง → สำนักงาน):** คอลัมน์ กอง/สำนักงาน, โครงการ, หน่วยเต็ม, โอนแล้ว, หน่วย Active, หน่วยว่างพร้อมขาย, หน่วยว่างไม่พร้อมขาย, %โอนแล้ว — แถวสรุปกอง (สีไล่ตามกอง) + แถวสำนักงานย่อย + แถว "รวมทั้งหมดทุกกอง" ท้ายตาราง (โทนฟ้าอ่อนเด่นชัด) คลิกหัวคอลัมน์เรียงลำดับได้

**ตารางรายละเอียดโครงการ:** ทุกคอลัมน์จากชีต "สรุปหน่วยเต็ม" ยกเว้นคอลัมน์สุดท้าย (`check`) รวม 33 คอลัมน์ — ไม่มีการกดกางแถวดูรายละเอียดเพิ่ม (ตัดออกแล้ว) ตารางเลื่อนแนวนอนได้

**Export:** ปุ่ม PDF (แดง, เปิดแท็บใหม่พิมพ์ได้) / Excel (เขียว) แยกอิสระต่อตาราง (สรุป+รายละเอียด)

**หัวตาราง:** ไล่สีพาสเทลสลับ 4 โทน (ฟ้า→ม่วง→มินต์→ทอง) ให้ดูมีชีวิตชีวาแต่ยังอ่านง่าย

### 4.3 Tab "หน่วย Active" (ระดับหน่วย/MAT)

**การ์ด KPI (7 ใบ แยกกัน แบบเดียวกับภาพรวม):** "หน่วย Active ทั้งหมด" (การ์ดรวม โทนเขียวมิ้นท์ไล่เฉด) + 6 การ์ดสถานะ **สีต่างกันทุกใบ**: (1)เช่า=เขียวมิ้นท์, (2)เช่าเหมา=ม่วง, (3)เช่าซื้อ=เขียว, (4)จะซื้อจะขาย=ทอง, (5)ติดค้ำประกันฯ=แดง, (6)รอโอน=น้ำเงิน — คลิกการ์ดใดก็กรองทั้งหน้าตามสถานะนั้น คลิกซ้ำหรือคลิก "ทั้งหมด" เพื่อยกเลิก

**ตัวกรอง:** กอง, ประเภทโครงการ, รูปแบบหารายได้ (ระดับโครงการ), ลักษณะอาคาร + ค้นหา (คลุม ชื่อโครงการ/รหัส/MAT/บ้านเลขที่/สำนักงาน) — cross-filter แบบเดียวกับภาพรวม

**กราฟ:** โดนัทตามกอง, อันดับสำนักงาน (ทั้งหมด), อันดับโครงการ (Top 10) — นับจากจำนวนหน่วยที่ผ่านตัวกรอง

**ตารางสรุป (กอง → สำนักงาน):** ไม่กดการ์ดสถานะ = โชว์ครบ 6 คอลัมน์สถานะ, กดการ์ด = เหลือคอลัมน์เดียวตามสถานะที่เลือก, กด "ล้างตัวกรอง" กลับมาครบเหมือนเดิม

**ตารางรายละเอียด (1 แถว = 1 หน่วย):** กอง, สำนักงาน, ประเภทโครงการ, รูปแบบหารายได้, ลักษณะอาคาร, รหัสโครงการ, ชื่อโครงการ, MAT, บ้านเลขที่, สถานะ, แหล่งที่มา (ชื่อชีต) + คอลัมน์อ้างอิงที่โผล่/ซ่อนตามสถานะที่กรอง:
- ไม่กรอง → โชว์ทั้ง `CUST_STATUS_NAME` และ `CONTRACT_STATUS` พร้อมกัน (แถวไหนไม่มีข้อมูลจากชีตนั้นแสดง "—")
- กรอง เช่า/เช่าซื้อ/จะซื้อจะขาย → เหลือ `CUST_STATUS_NAME`
- กรอง ติดค้ำประกันฯ/รอโอน → เหลือ `CONTRACT_STATUS`
- กรอง เช่าเหมา → ไม่มีคอลัมน์อ้างอิงเพิ่ม

**Pagination:** แสดงทีละ 300 แถว (ป้องกันเบราว์เซอร์ค้างตอนไม่กรองอะไร เพราะมีถึง 36,220 แถว) มีปุ่ม "ก่อนหน้า/ถัดไป" ท้ายตาราง — Export PDF/Excel ยังคงได้ข้อมูลครบทุกแถวไม่ตัดตามหน้าจอ

**⚠️ รอไฟล์ใหม่:** ตัวเลขในทุกที่ของ tab นี้**ยังไม่รวม** `CONTRACT_TYPE_CODE = 80` (ดูหัวข้อ 2.1) — เมื่อได้ไฟล์ Excel ฉบับที่แก้ไขแล้วจะกลับมาเพิ่ม mapping ให้ครบ

### 4.4 Tab "หน่วยว่าง" (ระดับหน่วย/MAT)

**การ์ด KPI (5 ใบ):** "หน่วยว่างทั้งหมด" (การ์ดรวม โทนทองไล่เฉด) + 4 การ์ดสถานะ: ว่างพร้อมขาย(เพื่อเช่า)=ทอง, ว่างไม่พร้อมขาย(เพื่อเช่า)=แดง, ว่างพร้อมขาย(เพื่อขาย)=ทอง, ว่างไม่พร้อมขาย(เพื่อขาย)=แดง

**ตัวกรอง:** กอง, ประเภทโครงการ, **รูปแบบหารายได้ (ใช้ TYPE_NAME ระดับหน่วยจริง ไม่ใช่ค่าระดับโครงการ)**, ลักษณะอาคาร + ค้นหา

**กราฟ + ตารางสรุป:** โครงสร้างเดียวกับ tab หน่วย Active ทุกประการ (โดนัท/อันดับสำนักงาน/อันดับโครงการ, ตารางสรุปคอลัมน์สถานะโผล่/ซ่อนตามที่กรอง)

**ตารางรายละเอียด (1 แถว = 1 หน่วย):** กอง, สำนักงาน, ประเภทโครงการ, รูปแบบหารายได้, ลักษณะอาคาร, รหัสโครงการ, ชื่อโครงการ, MAT, บ้านเลขที่, สถานะ, CONTRACT_STATUS, สิ้นสุดค้ำประกัน, วันที่ซื้อคืน, จำนวนวันซื้อคืน, หมายเหตุ, อ้างถึง (ไม่มีการโผล่/ซ่อนคอลัมน์ตามสถานะ เพราะมีแหล่งข้อมูลเดียว) — มี pagination เหมือนกัน (ข้อมูลน้อยกว่ามาก ไม่น่าจะหน่วง)

## 5) หลักการออกแบบที่ใช้ร่วมกันทุก tab

- **Cross-filter ไม่กรองตัวเอง**: dropdown แต่ละตัวคำนวณตัวเลือกจากตัวกรองอื่นที่เลือกไว้ทั้งหมด ไม่รวมค่าที่ตัวเองเลือกอยู่
- **การ์ด KPI = ตัวกรองในตัว**: คลิกการ์ดหรือ badge ใดก็ตามจะกรองทั้งหน้า (กราฟ+ตาราง) ตามนั้นทันที มีกรอบไฮไลต์สีของตัวเองบอกสถานะ + chip โผล่ในแถบตัวกรอง
- **Lazy loading**: tab ที่ยังไม่เคยคลิกเข้าจะยังไม่ประมวลผล/ถอดรหัสข้อมูลใดๆ
- **Pagination สำหรับตารางที่มีข้อมูลเยอะ**: ป้องกันเบราว์เซอร์ค้าง (ทำไว้ที่ตารางรายละเอียดของ tab หน่วย Active และหน่วยว่าง) — export ยังคงได้ข้อมูลเต็มเสมอ
- **Export แยกอิสระต่อตาราง**: ทุกตารางสรุป/รายละเอียด ในทุก tab มีปุ่ม PDF (แดง) / Excel (เขียว) ของตัวเอง

## 6) ประวัติการพัฒนา (สรุปย่อ)

1. สร้างแดชบอร์ดเริ่มต้น (การ์ด/ฟิลเตอร์/กราฟ/ตาราง/export) จากไฟล์ Excel ที่อัปโหลด — เฉพาะ tab ภาพรวม
2. แก้บั๊กกราฟว่างเปล่า (CDN ถูกบล็อก) → ฝังไลบรารีในไฟล์ทั้งหมด, ปรับตารางสรุปเป็น group by กอง, ปรับสีสดใส
3. จำกัด export ให้เหลือเฉพาะตารางสรุป+รายละเอียด, ย้ายปุ่มไปเหนือตาราง, ตรวจทานจำนวนสำนักงาน/สูตร COUNTIFS ทั้งหมด
4. ปรับ KPI เหลือ 4 การ์ด, เพิ่ม breakdown, กราฟผูกกับเมตริกที่เลือก, audit drill-down จาก 4 ชีตธุรกรรม (ตัด PII)
5. เปลี่ยนเทคนิคบีบอัดเป็น gzip+base64+DecompressionStream (ไฟล์เดียว), ปรับกราฟ ranking เป็น custom HTML
6. ปรับ UI รอบใหญ่: ตัดคำ "สำนักงาน" ในกราฟ, ลดพื้นที่โดนัท, ฟอนต์ใหญ่ขึ้น, ตารางรายละเอียดใช้ทุกคอลัมน์จากชีต (ยกเว้น check), หัวตารางสีพาสเทลสลับโทน, cross-filter ไม่กรองตัวเอง, การ์ด KPI คลิกเป็นตัวกรองได้, badge ย่อยในการ์ดคลิกกรองได้
7. **ตรวจสอบสูตร COUNTIFS ทั้งหมดอย่างละเอียด** (อ่านทีละคอลัมน์ ยืนยัน join key/เงื่อนไขที่แท้จริง) พบช่องว่าง `CONTRACT_TYPE_CODE=80` ที่ตกหล่นจากสูตรเดิม — บันทึกไว้รอไฟล์ใหม่
8. สร้าง **tab "หน่วย Active"** — join 3 ชีตธุรกรรมตามสูตร COUNTIFS, ตรวจนับยืนยัน 36,220 หน่วยตรงกับผลรวมเดิม 100%, ทำการ์ด/ตาราง/export ครบ
9. แก้ปัญหาเบราว์เซอร์ค้างตอนเปิด tab หน่วย Active (ตารางรายละเอียดเรนเดอร์ 36,220 แถวพร้อมกัน) → เพิ่ม pagination หน้าละ 300 แถว, แก้บั๊กปุ่มเรียงลำดับเรียก refresh ผิด tab
10. ปรับการ์ด KPI ของ tab หน่วย Active จาก "1 การ์ดใหญ่ + badge ข้างใน" เป็น "7 การ์ดแยกกัน" แบบเดียวกับภาพรวม
11. สร้าง **tab "หน่วยว่าง"** — join ชีต "หน่วยว่าง" เพิ่มคอลัมน์ CONTRACT_STATUS/END_GUARANTEE_DATE/REDATE/DATEK/STOCK_RMK/REF_NO (ต้องดึงข้อมูลใหม่จาก Excel เพราะไม่เคยฝังไว้ในไฟล์), ตรวจนับยืนยัน 2,660 หน่วยตรงกับผลรวมเดิม 100%, ใช้ TYPE_NAME ระดับหน่วยแทน "รูปแบบหารายได้" ระดับโครงการ, เปลี่ยนสีการ์ด KPI ของ tab หน่วย Active ให้แต่ละสถานะมีสีต่างกัน (เดิมเป็นเขียวมิ้นท์เหมือนกันหมด)
12. ปรับสีหัวตารางใน PDF export ให้อ่อนลง (จากน้ำเงินเข้ม/ขาว เป็นฟ้าอ่อน/ตัวหนังสือเข้ม), ทดลองบังคับตัดคำทุกคอลัมน์แล้วพบว่ากินกระดาษ/ดูไม่สมส่วน → ปรับกลับให้ตัดคำเฉพาะที่จำเป็นแล้วสุดท้ายยกเลิกทั้งหมด กลับไปใช้พฤติกรรมยืดตามเนื้อหาปกติ
13. เพิ่มตัวกรอง **"สำนักงาน"** และ **"ชื่อโครงการ"** ในทุก tab (ภาพรวม/หน่วย Active/หน่วยว่าง) แบบ cross-filter เหมือนตัวกรองอื่น
14. ปรับตารางสรุปของทั้ง tab "หน่วย Active" และ "หน่วยว่าง" จากกลุ่มระดับ "กอง → สำนักงาน" เป็น **"กอง → โครงการ"** (1 แถว = 1 โครงการ) เพิ่มคอลัมน์ "ชื่อโครงการ" ถอดคอลัมน์ "จำนวนโครงการ" ออก (ไม่จำเป็นแล้วเพราะแต่ละแถวคือ 1 โครงการอยู่แล้ว)
15. เพิ่มคอลัมน์ **CONTRACT_TYPE_CODE** ในตารางรายละเอียดของ tab หน่วย Active (derive จาก source+status ที่ join ไว้แล้ว ไม่ต้องดึงข้อมูลใหม่) แสดงเฉพาะแถวจากชีต มีสัญญา
16. **แก้บั๊ก CUST_STATUS_NAME ว่างเปล่า** — พบว่า `AUDIT_DATA` ชุดเดิมไม่เคยเก็บค่านี้ไว้สำหรับแถวจากชีตมีสัญญา (เก็บเฉพาะ เช่าซื้อรอโอน/หน่วยว่าง) ดึงค่าจริงจากชีต มีสัญญา มาใหม่ทั้งหมด (`CS64`, 15,863 แถว) ดูรายละเอียดในหัวข้อ 9

## 9) บั๊กที่เจอและแก้แล้ว: CUST_STATUS_NAME ว่างเปล่า (tab หน่วย Active)

**อาการ:** คอลัมน์ `CUST_STATUS_NAME` ในตารางรายละเอียดของ tab "หน่วย Active" ว่างเปล่า **ทุกแถว** ที่มาจากชีต `มีสัญญา` (เช่า/เช่าซื้อ/จะซื้อจะขาย) แต่แถวจากชีต `เช่าซื้อรอโอน` (CONTRACT_STATUS) ปกติดี ไม่มีปัญหา

**สาเหตุที่แท้จริง:** ตัวแปร `AUDIT_DATA` (ก้อนข้อมูล `PB64`) ที่ใช้สร้าง tab "หน่วย Active" ทั้งหมด แท้จริงแล้วเป็นชุดข้อมูลที่สร้างไว้ตั้งแต่**ก่อนเริ่มทำ tab นี้ด้วยซ้ำ** (ทำไว้สำหรับฟีเจอร์ audit drill-down ในหน้าภาพรวมช่วงแรกของโปรเจกต์) ตอนนั้นออกแบบให้ฟิลด์ "หมายเหตุ/สถานะจริง" (`n`) เก็บค่าไว้**เฉพาะแถวจากชีต เช่าซื้อรอโอน กับ หน่วยว่าง เท่านั้น** — แถวจากชีต `มีสัญญา` ไม่เคยถูกดึงค่า `CUST_STATUS_NAME` (คอลัมน์ Y) มาเก็บไว้เลยตั้งแต่ต้น (ตรวจสอบแล้วพบว่า `n` ว่างเปล่า 100% สำหรับทั้ง 15,863 แถวจากแหล่งนี้) พอนำ `AUDIT_DATA` ชุดเดิมมาต่อยอดสร้าง tab หน่วย Active (เพื่อประหยัดเวลาไม่ต้องดึงข้อมูลใหม่ทั้งหมด) เลยติดข้อจำกัดเดิมมาด้วย

**วิธีแก้:** ดึงค่า `CUST_STATUS_NAME` (คอลัมน์ Y) จริงจากชีต `มีสัญญา` ใหม่ทั้งหมด คีย์ด้วยเลข `MAT` เก็บเป็นก้อนข้อมูลใหม่ `CS64` (~52.5 KB, 15,863 แถว ไม่มีค่าว่างเลย) โหลดตอนเปิดไฟล์ แล้ว join เข้ากับ `ACTIVE_UNITS` ด้วย MAT แทนที่จะพึ่งพา `AUDIT_DATA.n` สำหรับแหล่งนี้

**ตรวจยืนยันแล้ว:** จำนวนแถวที่ join ได้ (15,863) ตรงกับจำนวนหน่วยจากชีตมีสัญญาเป๊ะ ค่าตัวอย่างที่ได้: "กำลังผ่อนชำระ" (12,226), "ค้างชำระ" (2,687), "หยุดรับรู้รายได้" (904) ฯลฯ

**บทเรียน:** เวลาต่อยอด/reuse ข้อมูลที่เคยฝังไว้ในไฟล์จากฟีเจอร์เก่า ต้องเช็คให้ดีว่าฟิลด์ที่จะใช้ถูกออกแบบมาให้ครอบคลุมทุก source จริงหรือไม่ ไม่ใช่แค่เช็คว่า "มีฟิลด์นี้อยู่" เฉยๆ

| `CONTRACT_TYPE_CODE = 80` ในชีต `มีสัญญา` (1,585 แถว) | **รอไฟล์ใหม่ + รอตรวจสอบ** | ยืนยันสูตรที่ถูกต้องแล้ว (เจ้าของไฟล์แจ้งสูตรจริงมาให้): `code 80` จะถูก**รวมเข้ากับสถานะ "(3) เช่าซื้อ" เดิม** ไม่ใช่สถานะใหม่แยกต่างหาก — `=COUNTIFS(มีสัญญา!O:O,"20",...) + COUNTIFS(มีสัญญา!O:O,"80",...)` แปลว่าตอนแก้จริงแค่ปรับ join logic ของ "เช่าซื้อ" ให้ครอบคลุมทั้ง `O="20"` และ `O="80"` ไม่ต้องเพิ่มการ์ด/สถานะใหม่ในหน้า UI เลย (ยังคง 6 สถานะเท่าเดิม) — **รอไฟล์ Excel ฉบับใหม่ก่อนแก้จริง** ตามที่ตกลงกันไว้ คาดว่าตัวเลข "(3) เช่าซื้อ" และ "หน่วย Active" รวมจะเพิ่มขึ้นจากปัจจุบัน |

## 11) หากเปิดแชทใหม่

แนบไฟล์ต่อไปนี้พร้อมกับ README นี้:

- ไฟล์แดชบอร์ดปัจจุบัน `LAA_Dashboard_หน่วยความรับผิดชอบ.html` (แก้ไขต่อจากของเดิม)

แล้วบอกสิ่งที่ต้องการทำต่อได้เลย เช่น "ตรวจสอบ+เพิ่ม code 80", "เพิ่ม tab X", "แก้สไตล์ Y" ฯลฯ — ถ้าเป็นเรื่อง join ข้อมูลข้ามชีต ให้บอกด้วยว่าใช้คอลัมน์ไหนจากชีตไหนบ้าง (ตามแบบหัวข้อ 2 ของเอกสารนี้) จะช่วยให้ทำงานได้แม่นยำและเร็วขึ้น
